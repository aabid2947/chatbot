Design direction · v0.1

Calm, readable, and out of the way.

A chat UI style guide for our chatbot. It borrows the layout patterns people already know from Claude and ChatGPT, then sets its own colors, type and rules so it feels like its own product.

01 · References

What we take from each

Both apps solve the same problem in slightly different ways. We're not copying either one. We're picking the patterns that make chat easy to read and easy to use.

Claude

Warmth and reading comfort

  • Warm off-white background instead of pure white
  • Serif display type gives it a calm, editorial feel
  • Long answers read like a document, not a chat bubble
  • Generous line height and spacing
ChatGPT

Familiar structure

  • Single centered column, about 750px wide
  • User messages in a soft grey bubble on the right
  • Assistant replies as plain text, no bubble
  • Rounded "pill" composer pinned to the bottom
  • Small action row under each reply (copy, retry)
Ours

The blend

  • ChatGPT's layout, Claude's warmth
  • Indigo accent, already used in the app, for actions and focus only
  • Serif only for big headings. Everything else is Inter
  • Light and dark themes from day one

03 · Tokens

Color

Mostly warm neutrals. The accent is for things you can click or that have focus. It's never used for large areas or body text.

Typography

Inter for the interface and messages. Source Serif for page titles and empty-state headings only. JetBrains Mono for code.

04 · Components

Building blocks

Each piece with the states it needs to handle.

Messages

User: soft bubble, right side

Assistant: plain text with an avatar mark. No bubble, so long answers read like a page.

The typing dots show while waiting. They stop moving if the user has reduced motion turned on.

Buttons

One primary button per view at most. In the chat itself, the send button is the primary.

Empty state with suggestions

How can I help today?

Shown on a new chat. Clicking a suggestion fills the composer. It doesn't send straight away.

Error

Couldn't reach the server.

Errors sit just above the composer. The user's text goes back into the box so nothing is lost.

05 · Style rules

The rules

Short enough to remember. If a new screen breaks one of these, it needs a good reason.

One reading column.Messages and composer share a centered column no wider than 760px. Lines stay short enough to read comfortably.
Only the user gets a bubble.The user's message sits in a soft bubble on the right. The assistant's reply is plain text on the page.
Accent means "you can act here".Indigo is for the send button, focus rings, links and the selected state. Never for backgrounds or body text.
Warm neutrals, never pure white or pure black.The page is #faf9f6 in light and #1b1a18 in dark. Pure #fff is only for raised surfaces like the composer.
Serif for titles, sans for chat.Source Serif appears on page titles and the empty-state greeting. Messages, UI and labels use Inter.
Use tokens, not raw values.Every color, radius and spacing comes from the list above. If something is missing, add a token instead of a one-off value.
Every state is designed.Empty, typing, sent, error and long content (code, lists, very long words) all have a look before the screen ships.
Both themes, always.Each new component is checked in light and dark before it's done.
Readable at phone width.At 640px and below the sidebar hides, bubbles can grow to 90% width, and side padding is 16px.
Keyboard first.Enter sends and Shift + Enter adds a line. Focus is always visible. Focus goes back to the composer after sending.

✓ Do

  • Let assistant answers breathe. Use 24px between turns
  • Put copy and retry under replies, quiet until hovered
  • Keep the composer visible and pinned to the bottom
  • Name chats from their first message

✕ Don't

  • Put the assistant in a coloured bubble
  • Use the accent for decoration or big fills
  • Use Claude's or ChatGPT's logos, names or exact colors in the product
  • Add shadows to messages. Only the composer is raised
