Personal chatbot: final plan

A local chatbot for one person. It chats like a web LLM, answers and summarizes from uploaded PDFs, and keeps its memory sharp however long a chat gets. Everything runs on this machine. The LLM is local Claude Code, called fresh for every message.

The Claude call

claude -p
  --setting-sources local       # none of your settings, hooks or CLAUDE.md
  --disable-slash-commands      # no skills
  --tools ""                    # no shell, file or web tools
  --strict-mcp-config           # ignore every other tool server
  --mcp-config <per call>       # only our tools, scoped to this chat
  --allowedTools mcp__rag__*    # our tools run without prompts
  --no-session-persistence      # nothing saved, every call is stateless
  --system-prompt <ours>
  --output-format stream-json --include-partial-messages
  --model sonnet                # haiku for background jobs

Tested on 31 Oct 2026. Calls are stateless. Claude calls our tools and cites pages. It can't see your personal instructions. --safe-mode must not be used, because it also blocks our tools.

Claude Code still adds your email, Windows paths and OS version to every call. That's fine here, because the bot is only for you. Switching to the Anthropic API later means rewriting one file.

Conversations and history

  • Every conversation gets a conversation id when it's created. Every request about a chat uses that id.
  • Every message is saved in full, with its conversation id, who sent it, and when. The memory system never deletes anything.
  • You can fetch the whole history of any conversation by its id, in order.
  • Conversations can be listed newest first, renamed and deleted.
  • Each conversation gets a title from its first message, made in the background.

What each turn sends

Rebuilt from the database every time. It stays about the same size however long the chat gets.

System prompt fixed
Pinned facts about you ~500 tokens max
Rolling summary of the older chat ~1,000 tokens
This chat's PDFs: name, pages, one-line summary small
Last ~12 messages, word for word ~4,000 tokens
Your new message

Everything else, Claude fetches with tools only when it needs it.

Scoring never deletes anything. Only you delete facts. Note: the 0.7 marker sits at its real spot on the bar, just past 0.65.

You ask about it more → score goes up

Each time you bring it up, or Claude relies on it in an answer: +0.15, up to 1.0.

You ask about it less → score goes down

Each day you chat without it coming up: −0.005. (The plan first said −0.03. That was a maths slip: it would have unpinned a clear fact after 4 days, not 3 weeks.) Days you don't chat don't count, so a week away won't erase anything. A clear fact stays pinned about 3 weeks of normal use. One mention brings it back.

Unimportant, but you asked → promoted

If Claude has to dig something out of old messages, it becomes a fact at 0.65, pinned straight away. Then the normal rules apply.

Other rules

  • "Remember this" sets 1.0 and locks the fact, so it never fades. You can unlock it.
  • "Forget that" removes it.
  • A new fact that contradicts an old one replaces it, so you never get both.
  • If pinned facts outgrow ~500 tokens, the highest scores go in and the rest act as Known.
  • Every score change is logged, so the panel can show "used 4 times, last today."

How "used" is detected

After each reply, a background haiku call gets the latest exchange, the current facts, and the tools Claude used this turn. It answers with: facts to add, update or delete, which facts were used, and which old messages to promote. The app applies the score changes. Fading is worked out whenever a score is read, so nothing has to run each day.

Tools Claude can call

ToolWhat it does

get_document_summary(document)The stored summary of a whole PDF
read_pdf_pages(document, from, to)Exact text of specific pages, length capped
search_history(query)Older messages from this chat, word for word
search_memory(query)Known and Archived facts that match
remember_fact(fact)Pins and locks a fact when you say "remember this"

The tool address carries the chat id and a random secret, and only listens on this machine.

Build order

Around 1,500 lines in total. You can try each step in the browser as it lands.

  1. Chat and saving — app, database, Claude adapter, streaming, chat list. Check: chat with it, refresh the page, and the conversation is still there.
  2. Memory — facts, scores, rolling summary, history search, memory panel. Check: mention something early, chat a lot, ask later. Watch its score bar rise when you bring it up. Ask about a throwaway detail and see it show up as a new pinned fact.
  3. PDFs — upload, local storage, chunk and embed, PDF tools, summaries. Check: upload a PDF, ask a question, and see a page citation. Then ask for a summary.

Known limits

  • Each reply has a few seconds of startup before text appears, because every call starts a fresh Claude process. Streaming hides most of it.
  • It uses your Claude subscription's usage.
  • The embedding model is English-focused. A multilingual one can be swapped in later.
  • Scanned PDFs need OCR, which isn't included yet.
